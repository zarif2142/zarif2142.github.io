PDF tools that never see your files

qpdf in WebAssembly, Web Workers, and a security policy that makes uploading impossible, not just promised.

Free PDF sites ask you to upload documents to someone else's server just to merge two files. That never sat right with me. A PDF is often the most personal file on a computer: a tax form, a medical letter, a contract, a resume. Uploading it to a stranger's server to change one page is a bad trade, and it is the trade every free PDF site asks you to make.

I built PDF Tools so the trade is never needed. It is thirteen tools that run entirely in your browser: edit PDF, fill and sign, compress, merge, organize pages, split, images to PDF, PDF to images, convert images, add password, remove password, remove hidden metadata, and PDF info. Your files never leave your device, because the tools never send them anywhere. That is not a promise in the copy. It is how the thing is built.

The engine is qpdf, compiled to WebAssembly, running inside Web Workers. WebAssembly is what lets a program written in another language run in a browser at near-native speed. Web Workers are what keep it off the main thread, so the page stays responsive while a file is being processed. You can compress a large PDF and still scroll the page. That matters more than it sounds: a tool that freezes the tab while it works feels broken, even when it is not.

Every output gets checked by a second, independent PDF engine. qpdf does the work, and pdf.js or PDFium reads the result back to make sure it is valid. A tool that silently corrupts a document is worse than a tool that fails loudly, so the check is not optional. If the two engines disagree, the tool says so. I would rather have a user retry than hand them a file they cannot open.

The privacy guarantee is enforced by the browser, not just promised in copy. The page carries a security policy that refuses any connection to another site, so even a bug could not upload a file. There is no server doing the work, and the page is blocked from connecting to one. You can test it yourself: once the page has loaded, turn on airplane mode. Everything keeps working. Closing the tab clears every file from memory. Nothing is saved anywhere.

The hardest tool to build was the editor. A PDF is not a document in the way a word processor understands one. It is a set of drawing instructions: put this text here, in this font, at this size. Turning that back into editable text means rebuilding paragraphs, headings and fonts from layout data, and letting the text reflow as you type. It works for ordinary documents. Very complex layouts, columns and tables, get simplified, and that limit is stated on the page instead of hidden. A tool that admits its limits is more useful than one that pretends.

HEIC photos were their own problem. iPhones save photos in HEIC, and most PDF tools cannot handle them. The conversion has to happen on the device too, or the privacy claim falls apart. The same rule applied to every tool: if a step needed a server, the step was wrong, and I rebuilt it until it did not.

One piece works differently, and it is important to say so plainly. The Claude-powered assistant lives on its own page, it is for my family only, it needs an access code, and it runs on a Cloudflare Worker. The thirteen tools never touch it, and the assistant never sees a file unless someone opens that page and pastes something in. The tools are the private part. The assistant is a separate, labelled exception, and keeping the two apart is the whole point. A privacy claim that hides its exception is not a claim at all.

The site works on phones, installs like an app, and works offline after the first visit. That last part is the real test of the design: if a tool needs a server, it cannot work offline. These do, because there was never a server to begin with.

It is live and in use, by my family first. The repo is public, and so is the security policy, because a privacy story only holds up if people can read the code for themselves. The lesson I took from it is simple, and it applies beyond PDFs: privacy is a property of the architecture, not a sentence in the marketing copy. If the design allows an upload, someone will eventually find a way to make one happen. The only way to be sure it cannot happen is to build a page that cannot connect to anything at all.
